# AI 代码同步规范

建立日期：2026-10-26

## 一、目标和边界

老师继续在本机开发；完成一个阶段后，将增量更新包和更新说明发给学生，由学生电脑上的 AI 完成检查、备份、合并、迁移、测试和必要修复。

这是代码更新流程，不是重新部署或复制老师数据库。文档本身不能替代修改后的源码；每次同步至少要有更新文件或可访问的 Git 提交，以及对应说明。当前仅建立规范和记录，没有发布新代码，也没有执行学生端同步。

默认 Windows 原生运行，不使用 Docker/WSL。保持现有界面和业务能力，不重新仿制页面。

## 二、管理范围

所有交付相对路径以学生压缩包解压后的 `Strawberry-Student-Windows` 目录为根，不写死学生盘符。

| 老师工作区相对路径 | 学生项目相对路径 | 说明 |
| --- | --- | --- |
| Newsmart-Strawberry/backend | Newsmart-Strawberry/backend | 平台 API、worker、业务代码 |
| Newsmart-Strawberry/web | Newsmart-Strawberry/web | Vue/Vite 前端 |
| Newsmart-Strawberry/scripts/windows | Newsmart-Strawberry/scripts/windows | 本地服务启动脚本 |
| strawberry_project | strawberry_project | 图片清洗 |
| strawberry_vision | strawberry_vision | YOLO 训练、验证、摄像头预测 |
| packaging/templates | 交付包根目录相应文件 | 部署工具模板，不能按老师路径直接覆盖 |

`packaging` 是老师侧制包工具，`delivery` 是生成物和发布基线，不是默认日常开发目录。修改部署模板后，要另行生成学生根目录对应更新文件。不要直接对 delivery 副本做功能开发而忘记记录。

本工作区根目录当前不是 Git 仓库。可以先采用“增量文件包 + 哈希清单”，未来有统一 Git 仓库后使用分支、提交和三方合并，不能假设现在已经存在远程仓库。

## 三、第一版基线

- 版本号：`student-2026.10.25-base`，这是本同步流程定义的发布标识，不是应用 package.json 版本。
- 文件：`delivery/Strawberry-Student-Windows-2026-10-25.zip`。
- SHA256：`dafb07d49d89f470faac2a6461418ea7ef0df849ad4c5ec0127ab676d403fba4`。
- 包内 `manifest.json` 是首次交付文件哈希清单。
- 解压目录可能在验证时被改动，因此基线以发布 ZIP 的实际内容为准，不以老师 delivery 解压目录的当前内容为准。

特别注意，首个交付副本与老师源码存在已知差异：

1. `Newsmart-Strawberry/scripts/windows/services.ps1` 有 `STRAWBERRY_SKIP_WORKER` 判断，首次部署先恢复数据库再启动 worker。
2. `Newsmart-Strawberry/backend/package/yuxi/repositories/detect_repository.py` 使用 `ROUND(AVG(maturity_ratio)::numeric, 2)`，修复 PostgreSQL 类型错误。
3. 部署时会重建 Python 环境和前端依赖路径；本地配置、登录凭据及数据库恢复标记属于学生机器生成状态。

后续更新不能将上述修复误当作学生无关修改覆盖掉。涉及对应文件时，要读取发布基线和老师新文件做三方对比，保留交付专用逻辑，或者明确提供经过测试的替代实现。

## 四、老师端每次修改后的记录

负责开发的 AI 在 `版本更新记录.md` 追加记录，至少说明：

- 本次修改的目标和原因。
- 涉及项目、真实相对文件路径以及新增/修改/删除/重命名操作。
- 需要的依赖、Python/Node 版本变化。
- 是否涉及数据库结构、配置项或数据迁移。
- 学生端是否需要重启前端、API、worker 或依赖服务。
- 本机实际测试结果、未测试项与已知风险。
- 当前状态：本机修改未发布、已制包待验证、已发布等。

不要求每次小改动都重新发布。允许多条“未发布”记录合并成一次增量发布，但不能漏掉累计改动。

## 五、发布更新包

建议目录形式如下，这是待发布时创建的结构约定，不代表已经有这些文件：

```text
student-update-2026.10.26-01/
  UPDATE.md
  update-manifest.json
  files/
    Newsmart-Strawberry/...
  base/
    Newsmart-Strawberry/...
  migrations/
  tests/
```

`files` 只放本次新增或变更文件；`base` 保存对应的上一发布版本文本文件以支持三方合并。数据迁移与测试目录按需存在。不能把包里没有某个文件理解为删除，删除必须逐项列出。

`update-manifest.json` 至少包含：来源版本、目标版本、适用平台、每项操作、相对路径、原文件 SHA256、新文件 SHA256、依赖变化、迁移编号。新增文件的原哈希为空，删除文件的新哈希为空。重命名须列明原路径和新路径。不得填占位哈希冒充真实校验。

发布前从正式基线构建更新结果，测试后再压缩并生成压缩包 SHA256。至少检查：不存在绝对路径或 `..` 越界路径、不夹带密钥/数据库/临时文件、增量应用后文件与目标清单一致、原基线修复未丢失。

学生可能仍在更早版本。更新包须明确仅适用于直接前一版，或另行提供累计更新包；不允许跳过必要数据库迁移。不同学生本地 AI 修复造成的源码差异必须作为本地修改处理。

## 六、学生端 AI 执行顺序

1. 阅读本规范、更新说明、包内清单及现有部署结果，识别实际安装根目录和当前发布版本。不能仅凭某个文件夹名认定版本。
2. 核对压缩包和更新文件哈希，检查路径边界。版本不匹配、缺基线或包损坏时停止覆盖并说明原因。
3. 比较学生现有文件、发布基线文件、老师新文件三方差异。当前文件等于旧哈希时允许替换；等于新哈希时视为已更新；其他情况属于本地修改，执行三方合并并记录。存在语义冲突或无法确认取舍时询问学生，不用整文件覆盖掩盖冲突。
4. 将即将变更的文件、本地配置以及版本记录备份到 `update-backups/<更新编号>/`，保存原哈希、操作记录和不存在文件的标记。数据库迁移前额外做逻辑备份并验证可读；备份可能含密钥，不提交到 Git。
5. 只停止确认属于该学生项目的受影响服务。前端更新可按需求重启 Vite；API/worker 源码变更后需要显式重启。不要杀死所有 python/node 进程。
6. 按清单执行合并或替换。删除仅限清单明确列出的源代码，删除前验证现有哈希及备份；禁止目录级递归清理。
7. 依赖变化在对应虚拟环境内安装，或按锁文件更新 pnpm 依赖。不改系统 Python；不把老师的 .venv 或 node_modules 直接覆盖过去。离线学生需要随更新提供相应依赖包，否则标记联网要求。
8. 如有迁移，按版本顺序执行一次，记录迁移编号；脚本需可重入或提供安全的已执行检测。不要重复导入首次部署的 business.dump，不要删除恢复标记后重跑数据库恢复。
9. 重启受影响服务，运行基础检查、该改动专项测试及关联回归。检查实际响应和日志，不以 HTTP 200 或端口开放代替业务通过。
10. 失败则记录完整错误、查明原因、最小修复并复测。对同一问题最多三轮有依据的修复，仍失败报告阻塞，不反复重装。学生端额外代码修复须记录为 local patch，不能冒称与老师目标文件完全一致。
11. 全部必测通过后更新 `student-version.json`，写入发布版本、更新时间、包哈希、结果报告路径及本地补丁清单。失败则记录尝试状态，保留原“最后验收通过版本”，不得假报升级完成。
12. 写 `UPDATE_RESULT.md`：更新内容、备份位置、测试结果、修复差异、未测试项、实际访问地址和回退办法。

首次采用此流程时，只有验证为原始发布包且代码符合基线，才可认定 `student-2026.10.25-base`。若学生已由 AI 修复过，不强制恢复原始源码；记录为“基线 + 本地修改”后做合并。

## 七、默认保护对象

下面内容默认不能随代码更新替换、删除或重置：

- `.runtime/local.env`、MQTT 凭据、API 密钥、JWT、本机 IP 和端口设置。
- `.runtime/data`、Neo4j 数据目录、对象存储、Redis 数据、业务数据库及学生后来创建的知识库/知识图谱。
- `backend/saves` 中的图片、共享文件、模型、智能体/用户文件和日志。确有代码模板变更时逐文件说明，不能整体覆盖 saves。
- `strawberry_project/images`、`output`；训练项目的数据集、标注、`weights`、`runs` 和训练报告。
- 各项目 `.venv`、`web/node_modules`、IDE 本地配置和学生未提交源码。
- `backup/restored.json`、`LOGIN.txt`、`student-version.json` 及更新备份。

确需更新模型或教学数据时，作为显式的独立资源更新处理，说明版本、来源、用途、大小、SHA256、保留旧版本和切换方案；不能以同步源码为名替换学生成果。

## 八、验收与回退

必测范围随变更决定。最低要求：后端健康与真实登录、受影响页面无加载错误、专项功能真实可用、关键业务数据未丢失。涉及识别需真实图片推理；涉及共享需上传/下载及 SHA256；涉及 YOLO 需检查参数、数据划分及实际短训练/验证；涉及 AI 需检查 worker 与外部模型错误。

部署测试禁止直接发送真实设备控制命令。摄像头、硬件、云服务缺失时记录 NOT_TESTED/BLOCKED，不伪造通过。知识库最初未打包不代表学生以后新建的库可以被删除。

回退时停止本项目受影响服务，按备份清单恢复旧代码、依赖和版本记录后复测。数据库迁移如不向后兼容，不能只回退代码；必须先保存更新后新产生的数据，再由用户确认恢复备份或执行经过验证的逆向迁移。不要自动覆盖学生升级后新增数据。

## 九、交给学生 AI 的提示词

> 请阅读本次 UPDATE.md、update-manifest.json 和 AI代码同步规范.md，在本机对草莓项目执行增量更新。先确认版本并备份，保留数据库、知识库、图片、模型、配置和我的本地代码修改。按三方差异合并，完成必要依赖和迁移后实际测试；发现问题定位修复并复测。禁止重新导入初始业务库、整目录覆盖或跳过冲突。全部必测通过后更新 student-version.json，并输出 UPDATE_RESULT.md；未测试或外部依赖阻塞如实注明。
