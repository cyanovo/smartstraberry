# 给学生电脑 Agent：草莓平台累计升级

目标版本：`student-2026.10.27-01`。这是已有安装的代码升级包，不是首次部署包。请完整阅读本文件、`AI代码同步规范.md`、`update-manifest.json` 和 `VALIDATION.md` 后操作。Windows x64 原生，不使用 Docker/WSL。

## 1. 适用版本和内容

支持 2026-10-25 首发包、2026-10-26 完整包，以及已经应用 `student-update-2026.10.26-01` 的安装。无需先逐个安装旧更新。先识别安装根目录，不照抄老师盘符。

本次包括病害识别记录引用、问答流式与工具展示、照片集批量导入与下载、删除图片同时删除关联病害记录、物联网设备开关、最新一条 AI 建议、一键关闭五路设备、局域网 MQTT 接入、LabelImg 修复脚本以及 YOLO 数据准备/图表/摄像头桌面工作台。逐文件范围以清单为准；没有列出的路径绝不代表删除。

`files/` 是新文件；`base/student-2026.10.25-base/` 和 `base/student-2026.10.26/` 是各来源的原始文件，不能把 base 复制进项目。清单每项 `old_sha256` 和 `operation_by_source` 都按来源版本索引；`new_sha256` 为目标值。部分条目对26日版本已相同，应跳过。

四份教学核心文件 `iot_service.py`、`field_analysis_service.py`、`strawberry_classifier.py`、`train.py` 保留26日发布版，不收录老师本机尚未完成的课堂编辑。不要从老师其他工作目录补拷这些文件，不覆盖学生已经编写的代码。老师原文件未被本次制包修改。

## 2. 环境与保护对象

沿用原部署环境：平台 API/worker、MQTT、YOLO 使用 Python 3.12.14；图片清洗/LabelImg 使用 Python 3.10.11；Node 22.19.0 和原 pnpm。优先使用安装目录内各项目 `.venv/Scripts/python.exe`，不要用系统 py 命令猜解释器。不要求换环境或重新装所有依赖。

本次无数据库结构迁移、无运行时新增依赖。清单中的 docs/package.json 与 docs/pnpm-lock.yaml 是累计文档站文件，不是业务前端依赖；仅运行平台无需安装 docs 依赖。GUI复用 Pillow、OpenCV、Ultralytics、Tkinter，先检查已有环境。

禁止覆盖 `.runtime`、`backend/saves`、数据库、图片、共享文件、知识库/图谱、数据集、标注、weights、runs、`.venv`、`node_modules`、密钥、本地IP配置、LOGIN.txt、backup/restored.json。Ollama与知识内容不在本包中；保留学生自行安装创建的内容。不得执行首次部署的 restore，不重新导入 business.dump，不通过清空数据解决问题。

## 3. 校验、备份、三方合并

1. 校验 ZIP 同名 `.sha256` 文件。解压到独立目录，检查所有路径无绝对路径、盘符或 `..`。用 `package-files.sha256.json` 验证包内文件，再核对清单中的新旧文件哈希。
2. 阅读学生的 student-version.json、snapshot.json、原 manifest.json 和部署报告。来源不明确时对比两套基线，不单凭目录名认定版本。原ZIP可用时核对清单登记的ZIP哈希；不要求再次下载完整包。无法判断实际来源或存在语义冲突时停止并询问。
3. 对每条：当前哈希等于新值则跳过；等于选定来源旧值则可替换；其他情况将学生当前文件、对应 base 文件、新文件做三方合并。新增路径已有内容也属于冲突。不要整目录覆盖。课堂代码和其他本地补丁必须保留。
4. 修改前备份所有待改文件、配置、依赖清单、版本记录到 `update-backups/student-2026.10.27-01/<时间>/`，记录不存在的文件及原SHA256。配置备份含秘密，不上传。备份失败不得继续。
5. 仅停止本项目 API、worker、Vite 及 MQTT 窗口，识别PID和命令行，不全局终止 python/node。数据库等服务保留。逐文件合并后核对结果哈希；合并不同于目标值时记录 local patch。
6. 保留 services.ps1 的 STRAWBERRY_SKIP_WORKER 判断和 detect_repository.py 的 `ROUND(AVG(maturity_ratio)::numeric, 2)`。已在交付候选中保留，不能拿老师原文件覆盖回去。

## 4. 启动和专项配置

先确认原有 PostgreSQL、Redis 等服务正常，再启动 API、worker、前端。不运行整套初始恢复。原启动入口继续可用。以下命令每行单独执行，先切换到所示项目目录。

在 Newsmart-Strawberry 目录重启 MQTT：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/windows/services.ps1 restart-mqtt
```

MQTT启动时自动发现在线物理网卡子网；同子网与本机不校验用户名密码，其他来源拒绝。设备填学生电脑当前局域网IPv4与1883，不照抄老师IP；换Wi-Fi后重启MQTT。API使用本机11883。仅用于可信教学网络，不映射公网，不关闭整机防火墙，需要时仅放行可信子网和必要端口。无线AP隔离、访客网络也会阻断设备接入。

在 backend 目录启动 API（worker由原独立入口启动）：

```powershell
.\.venv\Scripts\python.exe run_local.py
```

在 web 目录：

```powershell
pnpm dev
```

前端监听0.0.0.0，从5179开始遇占用递增，以终端实际URL为准；不要为了抢端口杀其他程序。不对外开放5050；前端经Vite代理访问本机API。

在 strawberry_vision 目录启动桌面工具：

```powershell
.\.venv\Scripts\python.exe vision_gui.py
```

数据准备要求解压后的图片/VOC XML，先核对类别语义再映射，输出目标已存在会拒绝覆盖。训练仍调用既有 train.py，不修改权重、数据集或训练结果。摄像头只加载可信来源模型。

LabelImg有矩形框崩溃时，先关闭标注工具，再在 strawberry_project 目录用其实际解释器执行：

```powershell
.\.venv\Scripts\python.exe fix_labelimg.py
```

脚本备份已安装canvas.py并可重复执行；未知版本报错时查明原因，不强行替换site-packages。不要把平台Python当作LabelImg环境。

## 5. 测试、自动修复和验收

先静态检查修改后的Python/Vue代码，再做以下验证。测试资源单独命名，不删除学生原数据。所有设备控制测试使用mock或专用隔离环境，禁止自动发送真实开关命令。

- 用学生现有账户真实登录，不重置密码；检查首页、图片集、成熟度、病害、共享、问答和物联网页面，记录浏览器错误及API/worker日志。
- 临时图片集导入子文件夹、导出ZIP，校验数量与原图SHA256；仅对测试图验证关联病害记录随删除一起消失，其他图片与成熟度记录不受影响。
- 病害记录引用、自定义问题不被改写、流式回答与工具结果、单条AI建议和建议时间；离线/过期建议不能执行。AI模型/知识库未配置要报告依赖缺失，不能编造检索成功。
- 物联网五个开关、AI建议在历史日志上方、一键关闭五路、失败提示与防重复；使用mock验证发送参数，不将“已发送”当实体已执行。真实硬件验收留给用户。
- 清洗环境导入cv2、LabelImg打开及创建标注；YOLO工作台启动、临时数据转换划分、图表查看。训练/摄像头条件具备再做短训练/验证及摄像头测试，不自动覆盖正式数据或自动下载大模型。
- 对比升级前后学生数据、模型、共享文件、知识库数量和关键样本，确认没有丢失。

在 backend 目录运行专项单元测试：

前端受控浏览器回归脚本在 backend/test/e2e：iot_switches.mjs、disease_care_suggestions.mjs、disease_care_smoke.mjs。使用可用Playwright与Chrome，按脚本环境变量指定 TEST_WEB_URL、PLAYWRIGHT_MODULE、CHROMIUM_PATH；不能照抄老师工具缓存路径。

发生失败时保存完整日志，定位配置/依赖/冲突/代码原因，最小修复并复测。每个问题最多三轮有依据的修复，仍失败报告阻塞。不得删测试、伪造通过或反复重装。缺硬件、摄像头、云服务如实写 NOT_TESTED/BLOCKED。

全部必测通过才更新 student-version.json：目标版本、原版本、升级时间、ZIP SHA256、报告路径、local patches。未通过保留最后验收通过版本，另记升级尝试状态。输出 UPDATE_RESULT.md，包含备份目录、实际修改清单、依赖/配置调整、逐项测试结果、修复记录、未测项、真实访问地址。
