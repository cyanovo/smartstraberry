# 代码审查技能

本技能用于系统化地审查代码，重点关注质量、安全与最佳实践。

## 何时使用

- 审查 Pull Request
- 分析代码潜在问题
- 确保代码质量标准
- 检查安全漏洞

## 审查流程

### 1. 代码质量分析

**检查项：**
- 命名规范（变量/函数用 camelCase，类用 PascalCase）
- 变量和函数名是否表意清晰
- 复杂逻辑是否有注释
- 格式与风格是否一致

### 2. 安全审查

**检查项：**
- SQL 注入漏洞
- XSS（跨站脚本）风险
- 输入校验是否充分
- 敏感数据是否暴露

### 3. 性能考量

**检查项：**
- 算法与数据结构是否高效
- 内存管理是否得当
- 是否有不必要的重复计算
- 数据库查询是否可优化

### 4. 错误处理

**检查项：**
- 是否有恰当的 try-catch
- 错误信息是否有意义
- 是否优雅降级
- 是否记录日志便于排查

### 5. 测试

**检查项：**
- 关键函数是否有单元测试
- 是否覆盖边界情况
- 是否需要集成测试

## 审查清单

- [ ] 遵循项目风格规范
- [ ] 函数职责单一、命名清晰
- [ ] 无硬编码密钥或凭据
- [ ] 实现了恰当的错误处理
- [ ] 已处理安全漏洞
- [ ] 已记录性能考量
- [ ] 新功能包含测试
- [ ] 文档已同步更新

## 最佳实践

1. **建设性**：着眼于改进，而非批评
2. **给示例**：指出问题时给出更好的写法
3. **分优先级**：先标关键问题，再提建议
4. **多提问**：理解代码决策背后的原因
5. **要具体**：引用具体行号并清楚解释
